# 日志使用规范

> 任务来源：`docs/EVOLUTION_PLAN.md` T0.2。本文档是全仓库应用日志的**唯一权威约定**，新代码必须遵守；存量代码按演进计划迁移（三个 PLC 驱动对应 T0.3~T0.5）。
> 相关规范：`docs/conventions/ERROR_HANDLING.md`（错误处理与"谁处理谁记录"原则）。

---

## 1. 基础设施现状（不变，仅约定用法）

- Serilog：Console + 文件 `logs/log-.txt`（按天滚动、保留 90 个、单文件 50MB），最小级别 Information，`Microsoft`/`System` 覆盖为 Warning，可由 appsettings `Serilog` 节覆盖。
- 增强器：`MachineName`、`ThreadId`、`ProcessId`（自动附加，业务代码无需关心）。
- 崩溃日志单独走 `logs/crash-yyyyMMdd.log`（GlobalExceptionHandler），不属于本规范范围。

## 2. 获取 Logger

- **唯一方式：构造函数注入 `ILogger<T>`**（`Microsoft.Extensions.Logging.ILogger<T>`），`T` 为当前类——`SourceContext` 自动带类名，不允许再手写类名/组件名前缀。
- **禁止**在业务代码中使用静态 `Serilog.Log.Logger` / `Log.Information(...)`（绕过滤级别与 SourceContext，且无法 Mock 测试）。宿主启动早期（DI 未就绪）除外。
- 字段类型声明为 `ILogger<T>` 完整泛型，不要退化为 `ILogger`（丢失 SourceContext）。

## 3. 日志级别约定

| 级别 | 何时使用 | 通信层示例 |
|------|----------|-----------|
| `Debug` | 诊断细节，生产默认关闭；高频路径（每次心跳、每次读写）只能用它 | 每次心跳成功、单次读写耗时 |
| `Information` | 重要的、低频的、状态迁移类事件；启动过程里程碑 | 设备已连接、设备已断开、看门狗启动/退出、插件启动 |
| `Warning` | 异常但已自愈或可继续运行；**状态从好变坏的瞬间** | 心跳失败判定掉线、首次连接失败转后台重连、配置项缺失用默认值 |
| `Error` | 操作失败且影响功能，需要人工关注；异常必须传异常对象 | 监督循环异常退出、写操作最终失败 |
| `Fatal` | 应用无法继续运行 | 仅全局兜底（GlobalExceptionHandler）使用 |

### 3.1 高频重复事件防刷屏（重要）

周期性循环（心跳 2s、重连退避 5s）中的日志必须遵守**状态迁移记录法**：

- **状态变化的瞬间记一条**（好→坏：Warning；坏→好：Information），持续期间不重复记录。
- 持续失败期间的每次尝试记 `Debug`（如每轮重连尝试），不记 Warning——否则现场一晚上的日志全是同一条重连警告。
- 同一故障**不允许**在驱动、服务、UI 各记一条（配合 ERROR_HANDLING.md 第 6 节"谁处理谁记录"）。

## 4. 消息模板约定

1. **中文**，面向运维/现场工程师，说清"什么设备、发生了什么、原因是什么"。
2. **结构化参数**：变量一律用 `{PropertyName}` 占位符（PascalCase），禁止字符串拼接/插值——拼接会丢失结构化检索能力。
3. **禁止 emoji**（✅❌🛡️💀⚠️🔄 等）：日志文件要进检索系统，emoji 无检索价值且部分终端乱码。
4. **禁止手工组件前缀**：`[看门狗]`、`[Scanner]` 这类前缀用属性替代（见第 5 节 `Component`），或交给 `SourceContext`。
5. **异常处理**：有异常对象时用 `LogError(ex, "...")` 重载，异常对象单独传；模板里不要再拼 `{Msg} = ex.Message`（堆栈会随异常对象完整输出）。
6. **敏感信息**：密码、完整连接串（含密码）、用户凭据**永不记录**；配置类日志只记非敏感字段。
7. 一条日志一个事实，不写复合长句。

## 5. 通信层必带字段

通信/设备相关日志必须携带以下结构化属性（有则用，无不强加）：

| 属性 | 说明 | 示例 |
|------|------|------|
| `Device` | 设备显示名（品牌-型号或配置名） | `Mitsubishi-Q (192.168.1.10:6000)` |
| `Component` | 子组件（需要区分时）：`Watchdog` / `Connector` / `Scanner` | 替代旧的 `[看门狗]` 前缀 |
| `Address` | PLC 地址（驱动层用） | `D100` |
| `Tag` | 逻辑点名（设备访问层用，T4.x 落地后） | `Line1.Oven.Temperature` |
| `Ip` / `Port` | 连接参数 | 连接成功/失败时 |
| `DurationMs` | 耗时（Debug 级诊断用） | 读写慢诊断 |

### 5.1 标准模板（T0.3~T0.5 按此统一）

| 场景 | 级别 | 模板 |
|------|------|------|
| 连接成功 | Information | `{Device} 已连接: {Ip}:{Port}` |
| 连接失败 | Error（带异常） | `{Device} 建立连接失败` |
| 主动断开 | Information | `{Device} 已断开` |
| 看门狗启动/退出 | Information | `{Device} 看门狗已启动，心跳地址: {Address}` / `{Device} 看门狗已退出` |
| 心跳失败判掉线（瞬间） | Warning | `{Device} 心跳读取失败，判定为掉线，原因: {Reason}` |
| 每轮重连尝试 | Debug | `{Device} 处于断开状态，尝试重连` |
| 监督循环异常 | Error（带异常） | `{Device} 看门狗循环异常退出，{RestartDelaySec} 秒后重启` |
| 读写失败 | Error（带异常或原因） | `{Device} 读取失败，地址: {Address}，原因: {Reason}` |

## 6. 应用日志 vs 审计日志（边界）

- **应用日志**（本规范）：技术诊断，写文件，面向开发/运维。通信细节、异常、性能。
- **审计日志**：业务事件，写数据库 `sys_audit_logs`，面向合规/追溯。登录、配置修改、PLC 写操作等"谁做了什么"。
- **禁止混用**：业务事件不能只写应用日志（丢追溯）；技术噪声不能写审计（污染台账）。PLC 写操作：审计记"某人写了某地址某值"，应用日志记"写入耗时/失败原因"。

## 7. 测试中的日志

- 单元测试不断言日志内容（脆弱）；需要验证"记了 Warning"时用 `ILogger<T>` 的 Substitute 验证调用次数，不验证文案。
